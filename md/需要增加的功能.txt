P0 — 稳定性与正确性（建议先做）
#	缺口	建议
1	JWT 无法登出 / 踢下线：SecurityConfig 里 .logout().disable()，token 签发后到过期前一直有效	Redis token 黑名单（qp:token:blacklist:{jti}，TTL = 剩余有效期）+ JwtAuthenticationFilter 查一次；或 t_user 加 token_version，改密码即失效
2	异步下单无持久化：seckillExecutor 是内存线程池，进程重启/宕机会丢任务，且此时 Redis 库存已扣但未成单	换成 Redis Stream / List 做可靠队列（消费确认 + pending 重试），或 RabbitMQ；保留线程池也要加“启动时扫描孤儿 key 补偿”
3	库存无对账：Redis 库存与 DB 长期漂移无人发现	新增 StockReconcileTask：比对 qp:seckill:stock vs t_train_stock.available_count vs t_seat 状态计数，不一致自动校准并告警日志
4	回源锁非分布式：MultiLevelCacheService 用本地 ReentrantLock，多实例会并发穿透到 DB	启用已预留的 RedisKeys.lock()，用 SET NX PX + 解锁 Lua（Redisson 更好）做成分布式锁，本地锁降级为二级防重
5	零测试：没有 *Test.java	至少补 3 类：Lua 脚本扣减/回滚的单测、SeckillService 幂等与补偿分支、MultiLevelCacheService 穿透/击穿场景（JUnit5 + Mockito，Redis 可用 Testcontainers）
